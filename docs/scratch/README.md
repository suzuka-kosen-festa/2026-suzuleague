# Scratch担当に渡すもの

## 2026-10-13: ステージ画面は、プロジェクトから作り直して配ることにした

本番で開くのは、プロジェクト `1364239598` そのものではなく、そこから作り直した2つの画面になった。
大画面に映す**入力なし**の画面と、出演者が答える**入力あり**の画面で、どちらも Render から配る。

- 大画面用: <https://suzuleague-cloud.onrender.com/stage/view/>
- 出演者用: <https://suzuleague-cloud.onrender.com/stage/play/>

絵・音・演出はプロジェクトのものをそのまま使う。入れ替えたのは、裏方PCとやり取りするスプライト「通信」のスクリプトだけ。
これで、下の「直してほしいこと」の3（途中で開き直すと崩れる）と、各チームの1問目でテンキーが出ない件（#53）は、**Scratch 側で直さなくてよくなった**。

Scratch担当にお願いしたいのは次の2つ。

1. **プロジェクトを直したら知らせる。** 作り直すまで本番の画面には出ない（開発側がコマンド1つで作り直す）
2. **メッセージと変数の名前を変えるときは、変える前に知らせる。** 「通信」は `初期化`・`4_正解発表`・`途中復帰_出題UI同期` などのメッセージと、`回答中`・`風船の数`・`予想%` などの変数を名前で使っている。一覧は [protocol.md](../protocol.md#元のプロジェクトに頼っていることscratch担当へ)

作り直しのときに見つけて、こちらで補ったこと（プロジェクト側でも直しておくと、TurboWarp で直接開いたときも同じになる）。

- **問題番号が1つ前にずれる**: 「コスチュームを（`☁ P2S_ROUND`）にする」は、値が数値で届くとコスチュームの番号で選ばれる（3問目なのに「2」が光る）。裏方PCが値を文字列で送るようにして解消した
- **2チーム目から、チーム名の札が出ない**: `初期化` の直後に `1_チーム紹介` を送っているので、札のクローンができる前にメッセージが通り過ぎる。作り直した画面では、少し待ってから送っている
- **途中から画面を組み立てるとき、問題文の絵が切り替わらない**: スプライト「問題」の `途中復帰_出題UI同期` の受け手に、コスチュームの切り替えがない
- **`途中復帰_背景同期` は、背景がすでに合っているとゲームオーバーの背景にする**: 各条件に「背景が◯番でない」が入っているので、合っているときは最後の「でなければ」に落ちる
- **5問目でゲームオーバーになると、GAME OVER の文字が次のチームにも残る**: 文字を隠すのは「次の問題へ」のときだけで、チームが替わるときに消す処理がない（次のチームのタイトルに重なる）

## 問題文リスト（`問題文リスト.txt`）

Scratch の表示用リスト `問題文` に取り込むテキスト。**行番号 = 問題ID**（チーム1が1〜5、チーム2が6〜10…）。

**2026-10-04 に本番問題を企画側の問題表に差し替えたため、Scratch 側のリストは20問すべて古いまま**になっている
（文言だけでなく、チームへの割り当て・順番も変わった）。このままだと、出演者の画面に**違う問題**が出る。

取り込み方:

1. Scratch エディタでプロジェクト `1364239598` を開く
2. ステージの変数 `問題文` のリストモニターを表示し、右クリック →「読み込み」
3. このファイルを選ぶ（1行1問・20行）
4. 保存して共有し直す

取り込んだかどうかは、開発側が Scratch API で照合できる（`docs/status.md` の「Scratch側との結合」参照）。

作り直すとき:

```bash
uv run python -m suzuleague.questions > "docs/scratch/問題文リスト.txt"
```

## 直してほしいこと（2026-10-06 の実機確認で分かったこと）

本番プロジェクト `1364239598`（2026-10-04 更新版）を、司会者画面・観客ページとつないで1チーム5問を通した。
進行・数字キーの回答・バルーンの数（裏方PCと一致）は正しく動いた。直してほしいのは次の点。

### 1. 問題文リストを新しくする（10/7 のデモまでに必須）

上の「問題文リスト」の取り込み。実機確認でも4問目で、Scratch は「BeRealをダウンロードしている人の割合は？」、
観客ページ（正しいほう）は「高専に入学して赤点を取ったことはある」になった（[#50](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/50)）。

### 2. 変数モニターを隠す（デモまでに）

出演者に見える画面に、変数モニターが出たままになっている。

- 左上の `☁ P2S_TEAM`
- 右上の「回答中」

### 3. チームの途中で開き直しても、今の画面を出せるようにする（10/17 目安）

チームの途中（例: 1問目の正解発表）で再読み込みして緑の旗を押し、裏方から今の状態を送り直すと、画面が崩れる。

- 正解発表の画面で、タイトル「パーセントバルーン」と「GAME OVER」が重なり、バルーンの数字が空になる
- 2問目に進んでもタイトルが問題文に重なったまま。左上の問題番号は「1」が光る（本当は2問目）
- 次のチームが登場（ステート1）すれば元に戻る

今の作りは「チーム紹介→風船登場→次の問題…」を頭から見てきた前提になっている。開き直すと `直前QID` などが 0 に戻り、
チームの2問目以降を最初に受けると `進行_次の問題へ` に入るため、風船の登場やタイトルを隠す処理を通らない。
**裏方からは毎回すべての変数（`P2S_STATE`・`P2S_ROUND`・`P2S_QID`・`P2S_BALLOONS`・`P2S_CORRECT`）を送っている**ので、それを使って画面を組み立ててほしい。

- 左上の問題番号を `P2S_ROUND` で決める（`問題数` スプライトの「次のコスチューム」を「コスチュームを `P2S_ROUND` 番にする」に）
- 緑の旗の後、ステート1以外（2〜7）を最初に受けたら、タイトルを隠し、バルーンを `P2S_BALLOONS` 個にして今の問題の画面にする

本番で端末がスリープや再読み込みをしても困らないようにするため（[#52](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/52)）。
直したら、開発側が実機で確かめる。

### 4. （任意）全体結果の画面

全体結果（ステート8）を受けても、5問目の結果が出たままになる。結果は観客ページと司会者画面で見せるので必須ではないが、
「終了」などに切り替わると出演者に分かりやすい。
