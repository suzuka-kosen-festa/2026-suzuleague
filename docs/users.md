# 使う人と画面

**誰が・どこで・何を見て・何をするか**を整理したもの。画面や機能を足すときは、まずこの表のどの人のためのものかを決める。

10月上旬のデモ会で「足りない画面」がまとめて指摘されたのは、この整理をしないまま画面を作っていたため。
とくに**進行を操作する司会が、開発者向けの黒い画面（CLI）しか持っていなかった**ことが、いちばん大きな穴だった。

## 大前提：出演者の画面を大画面にも映す（2026-10-13決定）

**本番は、会場の大画面に Scratch のステージ画面を映す。** 10/13 のデモ会で、出演者の画面を観客にも見せることになった。
10/4 に決めた「プロジェクターや大画面は使わない」は、ここで改めた。

- **大画面**: 入力なしのステージ画面（テンキーがない）。出演者の予想・正解発表の演出・残りバルーンが出る
- **出演者**: ステージに置いた端末の、入力ありのステージ画面。数字キーで回答する
- **司会・観客**: これまでどおり自分のスマホ（司会者画面・観客ページ）

2つのステージ画面は、Scratch担当のプロジェクトから作って Render から配る（[protocol.md](./protocol.md#ステージ画面は元のプロジェクトから作り直して配る)）。
どちらも観客ページと同じ進行の配信を受けるので、裏方PCが1回進めれば全部の画面がそろって進む。

司会者画面・観客ページ・出演者の回答画面（予備）は、スマホの縦画面で使える作りのままにする。
スマホ用の出演者の回答画面は、ステージの端末が使えないときの**予備**として残す。

## 画面ごとの詳細

### 司会者画面

- **使う人**: 司会。マイクを持ったまま、手元のスマホで操作する
- **中身**:
  - **必須**: 進行の操作。「次へ」「回答の代理入力」。ボタンには、押すと何が起きるかを書いておく
  - **あるとよい**: 今の問題の確認（問題文・正解・出演者の回答・残りバルーン）。正解は押したときだけ表示する
  - **出さない**: 台本のセリフ・BGMの合図。司会は紙の台本を使う
- **守ること**: 合言葉がないと操作できないこと。URLが観客に漏れても進行を乗っ取られないようにする
- **Issue**: [#33](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/33)

### ステージ画面（出演者用）

- **使う人**: ステージ上の出演者
- **置き場所**: ステージに置くPCかタブレット1台。<https://suzuleague-cloud.onrender.com/stage/play/> を開き、画面を1回クリックする
- **中身**: 問題文・バルーン・数字キーでの回答入力・正解発表の演出・チーム結果・全体結果（チームごとの残りバルーン・順位・優勝）。チーム名は、`teams.json` を作ってから作り直すと札とカードに出る（それまでは「チーム1」のような番号）
- **回答の届き方**: GO を押すと `☁ S2P_ANSWER` に書き、裏方PCが受け取る。司会者画面に「届いた回答」として出る。司会が代理入力したときは、テンキーが引っ込んでその回答が画面に出る
- **チーム結果**: 右のバルーンの表示が「誤差」から「獲得ポイント（残りバルーン）」に切り替わる
- **開き直しても戻る**: どの段階で再読み込みしても、1回クリックすれば今の画面になる。司会者画面の「Scratch に今の状態を送り直す」でも、開いたまま画面を組み立て直せる
- **注意**: クラウド変数はだれでも書き込めるので、悪意のある観客が回答を書き換えることは理論上できる。文化祭の範囲では許容する。気になる場合は下の回答画面（合言葉付き）に切り替える
- **元の画面**: Scratch担当のプロジェクトをそのまま開く `https://turbowarp.org/1364239598?cloud_host=wss://suzuleague-cloud.onrender.com` も引き続きつながる。ただし途中で開き直すと崩れる（[#52](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/52)）

### ステージ画面（大画面用）

- **使う人**: 観客（と会場の全員）。操作する人はいない
- **置き場所**: 大画面につなぐPC1台。<https://suzuleague-cloud.onrender.com/stage/view/> を開いて1回クリックし、右上のボタンで全画面にする
- **中身**: 出演者用と同じ画面から、テンキー・GO・Delete を外したもの。出演者が答えた時点で予想が出る
- **守ること**: この画面からは回答を送れない（`S2P_*` に書き込めない作りにしてある）。クリックしても何も起きない
- **観客ページとの関係**: 観客ページは、この画面のゲージが止まるまで正解を出さない（15秒待つ）

### 出演者の回答画面（予備）

- **使う人**: Scratch の端末が使えないときの出演者（回答する人のスマホ）
- **中身**: 今の問題文 → %を入力して決定 → 正解発表とチームの残りバルーン
- **正解の出方**: 正解発表から15秒（ステージ画面の演出が終わるまで）は、正解も減ったバルーンも出ない
- **守ること**: **観客がなりすまして回答できないこと。** 今登壇しているチームだけが回答できるよう、司会者画面に出す数字の合言葉を入力してから使う
- **Issue**: [#42](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/42)

### 観客ページ

- **使う人**: 観客
- **入口**: QRコード → <https://suzuleague-cloud.onrender.com/suzuleague.html>（ログイン不要）
- **中身**: ニックネーム入力 → 出題 → スライダーで回答 → 正解発表で自己採点（**ステージの回答も表示**） → チーム結果（自分の観客ランキングの順位） → 全体結果。進行と自動で同期する
- **ランキング**: 成績（20問の誤差の合計。未回答は1問50）とニックネームだけを送る（#36・#37）
- **注意**: 途中から参加する人・リロードする人がいる前提で作る。他の観客の回答は出さない

### リザルト

- **使う人**: 全員（表彰式。台本の 37:00「全チーム登場」から）
- **中身**: 4チームの順位と残りバルーン、優勝チーム、**景品（お菓子の詰め合わせ）の案内**、観客ランキングの上位、自分の順位
- **出し方**: 全体結果（`P2S_STATE=8`）になったら、観客ページ・出演者の回答画面・司会者画面がそれぞれリザルトに切り替わる
- **注意**: 観客のニックネームが全員のスマホに出る。不適切な名前は司会者画面の「観客ランキング」から隠せる（#39）
- **Issue**: [#35](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/35)・[#38](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/38)

## 1回の進行で、誰が何を見ているか

| 進行（`P2S_STATE`） | 司会（司会者画面） | 出演者と大画面（ステージ画面） | 観客（観客ページ） |
|---|---|---|---|
| 0 待機 | 開演前の確認 | 待機画面 | QRを読み取り、ニックネームを入力 |
| 1 チーム紹介 | インタビュー | チーム名とタイトル | 「チーム◯の登場」 |
| 2 出題 | 問題文・出典を読む | 問題文 | 問題を見る |
| 3 回答受付 | シンキングタイム | 出演者が**数字キーで%を入力して決定**。大画面には決定した予想が出る | スライダーで回答 |
| 4 正解発表 | 「回答者の答えは◯◯%！正解は…」。15秒は「次へ」を押せない | ゲージが動いて約13秒後に正解が出て、バルーンが割れる | ゲージが止まるまで「正解は…？」。そのあと自分の結果・出演者の結果 |
| 5 ラウンド結果 | 残りバルーンを読む | 残りバルーン | 残りバルーン |
| 6 チーム結果 | クリア／失敗・インタビュー | クリア／失敗 | 自分の結果 |
| 8 全体結果 | 表彰式 | チームごとの残りバルーン・順位・優勝 | リザルト・自分の順位 |

## 前提にしていること

違っていたらこの文書を直し、関係する画面の作りも見直す。

- **進行の中心（Python）は1台のPCで動かす。** このPCは誰も見ない裏方で、ステージ袖などに置く
- **出演者用のステージ画面は、ステージに置く別の端末で開く**（裏方PCと兼ねてもよいが、出演者が触れる位置に置く必要がある）
- **大画面用のステージ画面は、大画面につないだPCで開く**（裏方PCと兼ねてもよい。ネットにつながっていればどのPCでも開ける）
- スマホはこのPCに直接つながない。会場Wi-Fiでスマホから PC に届く保証がないため、**すべてのスマホ画面は Render のサーバに置き、Render を郵便受けにして PC とやり取りする**
  - 状態の配信（全員向け）: これまでどおりクラウド変数（`P2S_*`）
  - 操作・成績（と予備の回答画面からの回答）: Render のHTTPS API。合言葉はヘッダで送るので、他の端末には流れない
  - ステージ画面（出演者用）からの回答: クラウド変数（`S2P_ANSWER`）
- 裏方PCは `launcher/スズリーグ.app` を開くだけで起動でき、ターミナルは使わない。PCのブラウザにも同じ司会者画面が開く（予備。観客ランキングの操作はスマホの司会者画面でだけできる）
- Render に届かないときに備え、司会者画面はPC上でも開けるようにしておく（ターミナル版の起動とCLIも予備で残す）
- 進行は操作のたびに保存する。裏方PCが落ちても、アプリを開き直して「続きから」を選べば落ちる前の状態から再開できる（[#51](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/51)）
- 誰が何問目を答えるかは司会がその場で決める。システムは回答者を管理しない（[game-rules.md](./game-rules.md#誰が答えるかは司会が指名する2026-07-24決定)）
