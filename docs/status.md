### 仕組みの要点

```
司会のスマホ（司会者画面）──操作──▶ ┐
出演者のスマホ（回答画面）──回答──▶ ├ Render（cloud-server）◀──取りに行く・状態を預ける── 裏方PC（Python・進行の中心）
観客のスマホ（観客ページ）──成績──▶ ┘        │
            ◀──────── 進行の配信（クラウド変数 P2S_*）──────┘
            （ステージ画面の出演者用・大画面用も、この配信を受ける。出演者の回答は S2P_ANSWER で返す）
```

- 裏方PCは Render を郵便受けにして、司会の操作・出演者の回答を取り出す（スマホから裏方PCへは直接つながない）
- 司会者画面は合言葉（`HOST_TOKEN`）、出演者の回答はチームごとの4桁の合言葉で守る
- 画面の書き出しと本番との照合は `uv run python -m suzuleague.publish`（[手順](./development.md#観客用ページを更新する)）

### Scratch側との結合

本番で開くのは、このプロジェクトから作り直したステージ画面（10/13〜）。以下は、元のプロジェクトを TurboWarp で直接開いて確かめてきた記録。

本番プロジェクト [`1364239598`](https://scratch.mit.edu/projects/1364239598/)（2026-10-04 更新版）を、Scratch API での中身の確認と、
**TurboWarp で実際に開いて裏方PCとつなぐ自動テスト**の両方で確かめた（2026-10-04）。

- クラウド変数11個（P2S 7変数・`S2P_SEQ`・`S2P_ANSWER`・`S2P_ACK`・`HEARTBEAT`）をすべて実装済み
- **進行の配信**: 司会者画面の「次へ」で、Scratch 画面が チーム紹介 → 出題 → 回答受付 と進むことを確認
- **回答**: Scratch の回答（77%）が裏方PCに届くことを確認。ただしこれは scratchattach の不具合を直した後の話で、
  それまでは一度も届いていなかった（[落とし穴7](./development.md#7-scratchattach-の受信は自前サーバを指定しても公開サーバにつながる)）
- **実機での通し（2026-10-06）**: 進行・数字キーの回答・正解発表・バルーンの数（裏方PCと一致）・チーム結果（右のバルーンが「獲得ポイント」になる）まで確認
- **問題文はスプライト「問題」の画像で出す**。コスチューム名を「チーム番号-何問目」（例: `2-3`）にして、`☁ P2S_TEAM` と `☁ P2S_ROUND` で切り替える（リスト `問題文` は使われていない）。10/10 の確認で20問すべてが問題表と一致した（[#50](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/50) クローズ）
- **本番構成での通し（2026-10-12）**: 4チーム20問を全体結果まで確認。チームの切り替わりも正しい
- **チームの途中で開き直すと表示が崩れる**。10/11 に Scratch 側へ途中復帰の処理が入ったが、出題・回答受付の最中に開き直すと以降まったく進まなくなるなど、まだ崩れる（[#52](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/52)）。作り直した画面では解消
- **各チームの1問目は、出題から問題文が出るまで約8秒かかる**（効果音を鳴らし終えてから出す）。その前に回答受付へ進めるとテンキーが出ない（[#53](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/53)）。作り直した画面では、テンキーの件も8秒の待ちも解消（効果音と同時に問題文を出す。10/13 夜）
- **ステートは1つずつ間をあけて送る必要がある**。Scratch は `☁ P2S_SEQ` の変化を1コマごとに見ているだけなので、2つがほぼ同時に届くと間のステートを処理しない。裏方PC側で「次へ」の間隔を1秒以上あけている
- **Scratch は裏方PCのアプリより後に開く**。先に開くと、保存されている値を見て途中復帰の扱いになる
- Scratch側の対応ステートは 1〜6 と 8（全体結果では得点表のリストを出す）
- **出演者の手元の端末だけで使い、出演者は数字キーで回答する**と決定（2026-10-04、#41）→ 10/13 に、入力なしで大画面にも映すと改めた
- **本番で開くのは、プロジェクトから作り直したステージ画面**（2026-10-13）。上に書いた「開き直すと崩れる」「1問目のテンキー」「アプリより後に開く」は、元のプロジェクトを TurboWarp で直接開いたときの話で、作り直した画面には当てはまらない
- **10/13 の更新を取り込んだ**（2026-10-14。最終更新 10/13 18:01 UTC）。エキシビションモードの表示が入り、予想の数字は変数 `予想%` から、風船を割る数は `風船の数` と `☁ P2S_BALLOONS` の差から出すようになった。チーム名の札・待機画面・得点表の絵と、登場の効果音も差し替わっている
- **クラウド変数の値は文字列で送る**（2026-10-13）。数値で送ると、Scratch の「コスチュームを（`☁ P2S_ROUND`）にする」が番号で選ばれて問題番号が1つ前にずれる

- 150接続まで全員に配信が届くことを実測済み（遅延約120ms）

## リスク

| リスク | 影響 | 対応 |
|---|---|---|
| ステージ画面の端末がスリープ・再読み込みされる | 開き直すまで画面が止まる | 作り直したステージ画面は、再読み込みして1回クリックすれば今の画面に戻る（10/13）。端末のスリープ・自動ロックは切っておく |
| 作り直したステージ画面を実機で通していない | 電子黒板の PC や出演者の iPad で、音・全画面・動きの重さに問題が出るかもしれない | iPad 相当（WebKit・タッチ）の自動の確認は合格（10/21）。リハーサルまでに実機で通す（[#54](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/54)）。だめなら、元のプロジェクトを TurboWarp で直接開く（これまでどおりつながる。問題番号のずれは直っている） |
| 大画面のPCが重く、ゲージが遅れる | 観客ページが大画面より先に正解を出す | 観客ページは15秒待つ（大画面は実測13.3〜13.7秒）。実機で差を見る（[#54](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/54)） |
| 裏方PCのコードが本番の画面より古い（`git pull` 忘れ） | 同点優勝・開き直したときの GAME OVER の文字が出ない | 画面は古い形（`winner`）でも読めるので壊れない。アプリの起動時の照合で「画面が違う」と出たら `git pull` する（開発に使っている Mac は 10/14 に済ませた。本番で別のPCを裏方PCにするなら、そのPCでも行う） |
| Scratch担当がメッセージや変数の名前を変える | 作り直しが止まる（すでに配っている画面は変わらない） | 作り直しのコマンドが、なくなった名前を表示して止まる。名前を変えずに直したときも、アプリの起動時の照合で「ステージ画面が違う」と出る（10/21〜）。Scratch担当には名前を変える前に知らせてもらう。10/18 の更新で実際に止まり、10/19 に合わせた（[#61](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/61)） |
| Render が落ちる・届かない | **全員の画面が止まる**（ステージ画面も Render から配っている） | 代替手段（裏方PC上でサーバを動かし Cloudflare Quick Tunnel で公開）は確認済み。司会者画面は裏方PC上でも開けるようにする |
| 観客のニックネームに不適切な語 | 全員のスマホのリザルトに出る | 既存のNGワードフィルタは英数字しか見ないので、日本語はすり抜ける。**司会者画面の「観客ランキング」から隠す**（#39） |
| 観客が出演者になりすまして回答する | 出演者の得点が狂う | チームごとに発行する4桁の合言葉がないと回答できないようにする（#42） |
| 正解の出る司会者画面を観客に見られる | 答えが漏れる | 正解は押したときだけ表示する |
| 司会者画面のURLが漏れて、他人に進行を操作される | 進行が乗っ取られる | 合言葉がないと操作できない。合言葉はRenderの環境変数と裏方PCにだけ置く（リポジトリには入れない）。本番前に作り直すとより安全 |
| リハーサルの観客ランキングが本番に残る | 本番の順位がおかしくなる | リハーサル後に司会者画面の「ランキングをリセット」を押す（チェックリストに記載） |
| Render に届かない（司会の操作だけ） | スマホから操作できない | 裏方PC上の同じ画面で操作を続ける（CLIも残す） |
| 裏方PCの Python が止まる・誤って終了する | 止まっている間は進行できない | 操作のたびに進行を保存し、アプリを開き直して「続きから」で再開できる（[#51](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/51)。10/6 実装）。PC のスリープを切る・「終了する」は確認ダイアログを挟む |
| 会場ネットワークの品質 | 観客参加・ランキングが成立しない | 会場でのリハーサル（M3）で確認する |
| cloud サーバの単一障害点 | サーバが落ちると進行が止まる | 代替手段は確認済み（[手順](./development.md#本番サーバが落ちたときの代替手段)）。ランキングのデータはサーバ再起動で消えるが、イベント中は HEARTBEAT で起きている |
| Render 無料枠のスピンダウン（17分放置で復帰に22.8秒） | 開演直後にサーバが応答しない | **開演30分前に必ず起こす**。HEARTBEATを送り続けている間は眠らないことを実測済み |
| 観客数が `MAX_CLIENTS` を超える | 超過分の観客が静かに脱落する | 300に設定済み。配信は150接続、ランキングの一斉送信は300台まで実測で確認 |

### 10/4 に見つけて直した不具合

| 不具合 | 影響 | 対応 |
|---|---|---|
| Python の送信用接続が1〜2分ごとにサーバに切られ、直後の送信が黙って消える | 観客ページ（と Scratch 画面）の進行が途中で止まる | 接続を読み続けて ping に応答するよう修正。全20問のE2Eで再発なし（[落とし穴6](./development.md#6-送るだけの接続は12分ごとに切られ直後の送信が黙って消える)） |
| 観客ページで、2問目以降も1問目の回答のまま「決定済み」になる | 観客が2問目から答えられない | 問題ごとに回答を持つよう修正 |
| 観客ページで、正解発表とラウンド結果でバルーンが二重に減る | 観客の残りバルーンが実際より少なく出る | 問題ごとに1回だけ減らすよう修正 |
| **Scratch からの回答が Python に一度も届いていなかった**（7/23 に Render へ切り替えて以来） | 出演者が Scratch で答えても司会者画面に届かない（本番で代理入力しかできなくなる） | scratchattach の受信が自前サーバを無視して公開サーバにつながっていた。受信を自前の処理に置き換え、**本番の Scratch プロジェクトから回答が届くことを確認**（[落とし穴7](./development.md#7-scratchattach-の受信は自前サーバを指定しても公開サーバにつながる)） |
| Render が寝ているとダッシュボードが起動時に落ちる | 開演前に起こし忘れると進行を始められない | 接続に失敗したらサーバを起こして接続し直すようにした |

どれも7〜8月の検証では見つからなかったもので、**観客2人・全20問を通しで動かす E2E** と**本物の Scratch プロジェクトとの結合**で初めて出た。
