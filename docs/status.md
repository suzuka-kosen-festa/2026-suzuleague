### 仕組みの要点

```
司会のスマホ（司会者画面）──操作──▶ ┐
出演者のスマホ（回答画面）──回答──▶ ├ Render（cloud-server）◀──取りに行く・状態を預ける── 裏方PC（Python・進行の中心）
観客のスマホ（観客ページ）──成績──▶ ┘        │
            ◀──────── 進行の配信（クラウド変数 P2S_*）──────┘
            （ステージ画面の出演者用・大画面用も、この配信を受ける。出演者の回答は S2P_ANSWER で返す）
```

- 裏方PCは Render を郵便受けにして、司会の操作・出演者の回答を取り出す（スマホから裏方PCへは直接つながない）
- 司会者画面は合言葉（`HOST_TOKEN`）、出演者の回答はチームごとの4桁の合言葉で守る
- 画面の書き出しと本番との照合は `uv run python -m suzuleague.publish`（[手順](./development.md#観客用ページを更新する)）

### Scratch側との結合

本番で開くのは、このプロジェクトから作り直したステージ画面（10/13〜）。以下は、元のプロジェクトを TurboWarp で直接開いて確かめてきた記録。

本番プロジェクト [`1364239598`](https://scratch.mit.edu/projects/1364239598/)（2026-10-04 更新版）を、Scratch API での中身の確認と、
**TurboWarp で実際に開いて裏方PCとつなぐ自動テスト**の両方で確かめた（2026-10-04）。

- クラウド変数11個（P2S 7変数・`S2P_SEQ`・`S2P_ANSWER`・`S2P_ACK`・`HEARTBEAT`）をすべて実装済み
- **進行の配信**: 司会者画面の「次へ」で、Scratch 画面が チーム紹介 → 出題 → 回答受付 と進むことを確認
- **回答**: Scratch の回答（77%）が裏方PCに届くことを確認。ただしこれは scratchattach の不具合を直した後の話で、
  それまでは一度も届いていなかった（[落とし穴7](./development.md#7-scratchattach-の受信は自前サーバを指定しても公開サーバにつながる)）
- **実機での通し（2026-10-06）**: 進行・数字キーの回答・正解発表・バルーンの数（裏方PCと一致）・チーム結果（右のバルーンが「獲得ポイント」になる）まで確認
- **問題文はスプライト「問題」の画像で出す**。コスチューム名を「チーム番号-何問目」（例: `2-3`）にして、`☁ P2S_TEAM` と `☁ P2S_ROUND` で切り替える（リスト `問題文` は使われていない）。10/10 の確認で20問すべてが問題表と一致した（[#50](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/50) クローズ）
- **本番構成での通し（2026-10-12）**: 4チーム20問を全体結果まで確認。チームの切り替わりも正しい
- **チームの途中で開き直すと表示が崩れる**。10/11 に Scratch 側へ途中復帰の処理が入ったが、出題・回答受付の最中に開き直すと以降まったく進まなくなるなど、まだ崩れる（[#52](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/52)）。作り直した画面では解消
- **各チームの1問目は、出題から問題文が出るまで約8秒かかる**（効果音を鳴らし終えてから出す）。その前に回答受付へ進めるとテンキーが出ない（[#53](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/53)）。テンキーの件は、作り直した画面では解消
- **ステートは1つずつ間をあけて送る必要がある**。Scratch は `☁ P2S_SEQ` の変化を1コマごとに見ているだけなので、2つがほぼ同時に届くと間のステートを処理しない。裏方PC側で「次へ」の間隔を1秒以上あけている
- **Scratch は裏方PCのアプリより後に開く**。先に開くと、保存されている値を見て途中復帰の扱いになる
- Scratch側の対応ステートは 1〜6 と 8（全体結果では得点表のリストを出す）
- **出演者の手元の端末だけで使い、出演者は数字キーで回答する**と決定（2026-10-04、#41）→ 10/13 に、入力なしで大画面にも映すと改めた
- **本番で開くのは、プロジェクトから作り直したステージ画面**（2026-10-13）。上に書いた「開き直すと崩れる」「1問目のテンキー」「アプリより後に開く」は、元のプロジェクトを TurboWarp で直接開いたときの話で、作り直した画面には当てはまらない
- **クラウド変数の値は文字列で送る**（2026-10-13）。数値で送ると、Scratch の「コスチュームを（`☁ P2S_ROUND`）にする」が番号で選ばれて問題番号が1つ前にずれる

### 通信基盤

- 本番の接続先: **`wss://suzuleague-cloud.onrender.com`**（Render無料枠・Singapore・`MAX_CLIENTS=300`）。費用は0円
- 150接続まで全員に配信が届くことを実測済み（遅延約120ms）
- **無料枠の残量は 2026-10-04 時点で 0.08 / 750時間**。既存の2サービスはほとんど時間を使っておらず、10/31に枠切れで止まる心配はない（[#16](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/16) クローズ）
- サーバ停止時の代替手段（裏方PC上で動かして Cloudflare Quick Tunnel で公開）は実地で確認済み

詳細は [architecture.md](./architecture.md#同時接続数の上限とセルフホスト方針)。

### 確定したルール・方針

- **ぴったり賞は不採用**（2026-07-23）。本番では `--perfect-bonus` を付けない
- **誰が何問目を答えるかは司会がその場で決める**（2026-07-24）。システムは回答者を管理しない
- **サーバ費用は0円で組む**（2026-07-23）
- **本番まで依存を更新しない**（2026-07-23）。新機能も標準ライブラリで作る
- ~~プロジェクター・大画面は使わない（2026-10-04）~~ → **出演者の画面を、入力なしで大画面にも映す**（2026-10-13）。司会と観客はスマホ、出演者はステージに置いた端末のステージ画面で見て数字キーで回答する（スマホの回答画面は予備）。司会者画面は司会がスマホで操作する。台本は紙で持ち、システムでは出さない
- **ステージ画面は Scratch担当のプロジェクトから作り直して配る**（2026-10-13）。絵・音・演出は Scratch担当、裏方PCとやり取りする部分は開発側が持つ
- **観客ランキングを作る**（2026-10 デモ会）。これに伴い「観客の回答はサーバへ送らない」方針を改め、成績だけを送る形にした（[#7](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/7) を引き継いでクローズ）

| ステージ画面の端末がスリープ・再読み込みされる | 開き直すまで画面が止まる | 作り直したステージ画面は、再読み込みして1回クリックすれば今の画面に戻る（10/13）。端末のスリープ・自動ロックは切っておく |
| 作り直したステージ画面を実機で通していない | 大画面のPCや出演者の端末で、音・全画面・動きの重さに問題が出るかもしれない | リハーサルまでに実機で通す（[#54](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/54)）。だめなら、元のプロジェクトを TurboWarp で直接開く（これまでどおりつながる。問題番号のずれは直っている） |
| 大画面のPCが重く、ゲージが遅れる | 観客ページが大画面より先に正解を出す | 観客ページは15秒待つ（大画面は実測13.3〜13.7秒）。実機で差を見る（[#54](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/54)） |
| Scratch担当がメッセージや変数の名前を変える | 作り直しが止まる（すでに配っている画面は変わらない） | 作り直しのコマンドが、なくなった名前を表示して止まる。Scratch担当には名前を変える前に知らせてもらう |
| Render が落ちる・届かない | **全員の画面が止まる**（ステージ画面も Render から配っている） | 代替手段（裏方PC上でサーバを動かし Cloudflare Quick Tunnel で公開）は確認済み。司会者画面は裏方PC上でも開けるようにする |
| 観客のニックネームに不適切な語 | 全員のスマホのリザルトに出る | 既存のNGワードフィルタは英数字しか見ないので、日本語はすり抜ける。**司会者画面の「観客ランキング」から隠す**（#39） |
| 観客が出演者になりすまして回答する | 出演者の得点が狂う | チームごとに発行する4桁の合言葉がないと回答できないようにする（#42） |
| 正解の出る司会者画面を観客に見られる | 答えが漏れる | 正解は押したときだけ表示する |
| 司会者画面のURLが漏れて、他人に進行を操作される | 進行が乗っ取られる | 合言葉がないと操作できない。合言葉はRenderの環境変数と裏方PCにだけ置く（リポジトリには入れない）。本番前に作り直すとより安全 |
| リハーサルの観客ランキングが本番に残る | 本番の順位がおかしくなる | リハーサル後に司会者画面の「ランキングをリセット」を押す（チェックリストに記載） |
| Render に届かない（司会の操作だけ） | スマホから操作できない | 裏方PC上の同じ画面で操作を続ける（CLIも残す） |
| 裏方PCの Python が止まる・誤って終了する | 止まっている間は進行できない | 操作のたびに進行を保存し、アプリを開き直して「続きから」で再開できる（[#51](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/51)。10/6 実装）。PC のスリープを切る・「終了する」は確認ダイアログを挟む |
| 会場ネットワークの品質 | 観客参加・ランキングが成立しない | 会場でのリハーサル（M3）で確認する |
| cloud サーバの単一障害点 | サーバが落ちると進行が止まる | 代替手段は確認済み（[手順](./development.md#本番サーバが落ちたときの代替手段)）。ランキングのデータはサーバ再起動で消えるが、イベント中は HEARTBEAT で起きている |
| Render 無料枠のスピンダウン（17分放置で復帰に22.8秒） | 開演直後にサーバが応答しない | **開演30分前に必ず起こす**。HEARTBEATを送り続けている間は眠らないことを実測済み |
| 観客数が `MAX_CLIENTS` を超える | 超過分の観客が静かに脱落する | 300に設定済み。配信は150接続、ランキングの一斉送信は300台まで実測で確認 |

## 運用ルール

- 技術的な詰まり・仕様変更は **Discord で即時相談**する
- 通信仕様を変えたら `protocol.py` と `docs/protocol.md` を同時に更新し、
  **Scratch担当に必ず連絡**する（[手順](./development.md#通信仕様を変更するとき)）
- 問題を差し替えたら、`questions.py`・Scratchの問題の画像（スプライト「問題」）・観客ページ（`publish` で書き出してデプロイ）の**3か所を同時に更新**する
- **Scratch担当がプロジェクトを直したら、ステージ画面を作り直す**（`uv run python -m suzuleague.stage`）。作り直すまで本番の画面には出ない。`--check` で本番が最新かどうかを確かめられる
- **main（cloud-server は master）に直接コミットして push する**（2026-10-04〜）。cloud-server の push はそのまま本番デプロイなので、push 後は `publish --check` で照合する
- 本番投入前の確認事項は
  [リリースチェックリスト](./development.md#リリース本番投入チェックリスト) を参照

### 10/13 のデモ会で出たことと対応

| 出たこと | 対応 |
|---|---|
| **出演者の画面を観客にも見せたい** | Scratch担当のプロジェクトから、テンキーを外した**大画面用のステージ画面**を作って Render から配る（<https://suzuleague-cloud.onrender.com/stage/view/>）。出演者の予想は、裏方PCが新しい変数 `☁ P2S_ANSWER` で配る。出演者用・観客ページと同じルームに入るので、裏方PCが1回進めれば全部の画面がそろって進む |
| **Scratch の画面が崩れる** | 原因は2つあった。①**問題番号が1つ前にずれる**（3問目なのに「2」が光る）。裏方PCが値を数値で送っていたため、Scratch がコスチュームを名前ではなく番号で選んでいた。値を文字列で送るようにした。②**途中で開き直すと崩れる**（[#52](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/52)）。最新版（10/12 更新）でも、問題文が別の問題になる・正解発表で開き直して「送り直す」と風船が二重に割れる、などが残っていた。裏方PCとやり取りするスプライト「通信」を入れ替えた**出演者用のステージ画面**を作り、どの段階で開いても今の状態から画面を組み立てるようにした（<https://suzuleague-cloud.onrender.com/stage/play/>） |
| **観客の画面が先に正解を出す** | Scratch はゲージを動かして 13.3〜13.7秒後に正解を出す（実測）。観客ページは正解発表を受けてから**15秒**待つようにした（本番に反映済み）。司会が先へ進めたらすぐ出す |

作り直したステージ画面では、あわせて次も直っている。

- 各チームの1問目で、早く回答受付に進めてもテンキーが出る（[#53](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/53)）
- 2チーム目以降もチーム名の札が出る（元は1チーム目だけ）
- 5問目でゲームオーバーになっても、GAME OVER の文字が次のチームに残らない
- 司会が代理入力した回答も、ステージ画面の予想と演出に出る（元はテンキーで入れた数字しか使われない）
- 全体結果の得点表が、開き直しても出る（裏方PCが `☁ P2S_SCORES` で全チームの得点を配る）
- 裏方PCのアプリより先に開いても、途中の画面にならない

確かめ方: 元のプロジェクトを通しで動かしたときの画面と、作り直した画面の部品（位置・コスチューム・風船の数）を、自動操作のブラウザで時点ごとに比べた（3問ぶん14時点の通しと開き直し、2チームぶん45時点の通し）。テンキーは実際にクリックして、回答が裏方PCに届くことを確かめた。**実機（大画面につなぐPC・出演者の端末・音）ではまだ通していない。**

### 10/12 の実機テスト（本番構成・4チーム20問）

アプリの「本番」（仮のチーム名を入れた `teams.json`）で起動し、PCの司会者画面と TurboWarp の Scratch 画面で20問を全体結果まで通した。
20問とも問題文・問題番号・バルーンの数が司会者画面と合い、Scratch の数字キーの回答はすべて裏方PCに届いた。全体結果では Scratch に得点表が出た。見つかったのは次の3つ。

| 見つかったこと | 対応 |
|---|---|
| **各チームの1問目で、早く「回答受付」に進めるとテンキーが出ない**（4チームとも発生。「送り直し」で出る） | Scratch が1問目だけ約8秒の効果音を鳴らし終えてから問題を出し、その直後に入力できない状態へ戻しているため。Scratch担当に修正を依頼する（[#53](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/53)）。それまでは、1問目は Scratch に問題文が出てから「次へ」を押す |
| **「次へ」を続けて押すと、Scratch の正解発表が飛ぶ**（16問目で発生。前の問題の正解が画面に残った） | 2つのステートがほぼ同時（約0.03秒以内）に届くと、Scratch は後のほうしか処理しない（手元で再現）。**裏方PC側で、前の「次へ」から1秒たたない「次へ」を取り消すようにした**（押し間違いで2段階進むのも防げる） |
| Scratch担当が入れた途中復帰（#52）は、まだ崩れる場面がある | 手元で再現して3点を [#52](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/52) に書いた（出題・回答受付の最中に開き直すと以降まったく進まない／開き直した直後と次の問題の問題文が違う／旗だけ押し直すと止まる） |

### 10/6 の実機確認（#31 クローズ）

裏方PCは `スズリーグ.app`、司会者画面はスマホ、出演者は TurboWarp の Scratch 画面、観客はスマホで、デモ構成（1チーム5問）を全体結果まで通した。
進行・回答の受信・バルーンの数（裏方PCと Scratch で一致）・観客ページの再読み込み・全体結果はすべて正しく動いた。見つかったのは次の3つ。

| 見つかったこと | 対応 |
|---|---|
| Scratch の問題文が古い（4問目で観客ページと食い違った） | 既知。Scratch担当に取り込みを依頼する（#50）。10/7 に照合し、こちら側（問題表・`questions.py`・配布リスト・観客ページ）は一致、Scratch は差し替え前の問題のままと確認。10/8 に Scratch担当が差し替え、17問は一致。残り3か所（10問目が別の問題・16問目の画像の名前・8問目の誤字）を依頼した。10/10 に3か所とも直ったことを確かめ、20問すべて一致（#50 クローズ） |
| **チームの途中で Scratch を開き直すと、送り直しても表示が崩れる**（次のチーム登場まで戻らない） | Scratch 側が途中の段階からの表示に対応していない。Scratch担当に修正を依頼する（[#52](https://github.com/suzuka-kosen-festa/2026-suzuleague/issues/52)）。それまでは Scratch の端末をスリープさせず、開き直したら予備の回答画面に切り替える |
| PCの司会者画面（localhost）で「ランキングをリセット」を押すと必ず失敗する | 予備の画面にはランキングの機能がない。使えない画面ではボタンを出さないように直した（本番に反映済み） |

### 10/4 に見つけて直した不具合

| 不具合 | 影響 | 対応 |
|---|---|---|
| Python の送信用接続が1〜2分ごとにサーバに切られ、直後の送信が黙って消える | 観客ページ（と Scratch 画面）の進行が途中で止まる | 接続を読み続けて ping に応答するよう修正。全20問のE2Eで再発なし（[落とし穴6](./development.md#6-送るだけの接続は12分ごとに切られ直後の送信が黙って消える)） |
| 観客ページで、2問目以降も1問目の回答のまま「決定済み」になる | 観客が2問目から答えられない | 問題ごとに回答を持つよう修正 |
| 観客ページで、正解発表とラウンド結果でバルーンが二重に減る | 観客の残りバルーンが実際より少なく出る | 問題ごとに1回だけ減らすよう修正 |
| **Scratch からの回答が Python に一度も届いていなかった**（7/23 に Render へ切り替えて以来） | 出演者が Scratch で答えても司会者画面に届かない（本番で代理入力しかできなくなる） | scratchattach の受信が自前サーバを無視して公開サーバにつながっていた。受信を自前の処理に置き換え、**本番の Scratch プロジェクトから回答が届くことを確認**（[落とし穴7](./development.md#7-scratchattach-の受信は自前サーバを指定しても公開サーバにつながる)） |
| Render が寝ているとダッシュボードが起動時に落ちる | 開演前に起こし忘れると進行を始められない | 接続に失敗したらサーバを起こして接続し直すようにした |

どれも7〜8月の検証では見つからなかったもので、**観客2人・全20問を通しで動かす E2E** と**本物の Scratch プロジェクトとの結合**で初めて出た。
